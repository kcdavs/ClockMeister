# ClockMeister — project log

## What this is
Website for ClockMeister, a 3D-printed mechanical pendulum clock (~$350; deadbeat escapement, four-wheel train, spring-driven, exposed mechanism). Customers configure filament colors per part zone in a 3D view and buy via Stripe Checkout.

Design: Bauhaus / Mondrian (strong grid, black rules, off-white ground, deliberate primary colors, geometric type, subtle mechanical motion). Not template-looking.

Constraints: no database, no accounts, no server to maintain.

The owner is learning web development through this project (background: data analytics). ## Stack
- Next.js (App Router) + TypeScript, plain CSS (CSS Modules), no Tailwind

## 3D model
Source: Onshape "Right Assembly" (the whole clock; a mirrored left version exists but isn't used). 105 parts, ~322k triangles (2026-11-18 export; added 7× 3mm Dowel, a 5mm Tube and 4 M4 screws, all fixed hardware).
Optimization took it from 27.7 MB / 11,261 draw pieces to 2.0 MB / 93 pieces, no detail lost.

Part names are matched with a leading "Mirror " ignored (Onshape names the mirrored copies that way; the owner also has non-mirrored versions). Color zones live in `data/zones.ts` (`ZONES` list + `zoneForPart()` name rules). 15 selectable zones + fixed:
- Mainspring barrel (zone `barrel`): Mainspring Barrel (was the unnamed "Part 3", once wrongly called "Face")
- Numerals: the 72 small "Part N" segments, on the front frame — must contrast with the front frame (warning shown)
- Hands: Hour Hand, Minute Hand
- Drive wheel (zone `driveWheel`): Drive Wheel (was "Part 4"; the large first wheel of the train)
- Going train (zone `goingTrain`): 2nd/3rd/4th Wheel — drives site accent `--red`
- Escape wheel: Esc Wheel — drives site accent `--yellow`; Escape pallet: Esc Pallet
- Front frame: Front; Rear frame: Back
- Motion works, each its own zone: Motion works wheel (Motion Works, 89 mm; drives site accent `--blue`), Hour wheel (white Hour Wheel, 112 mm, behind the hands), Minute arbor (Minute Arbor, 32 mm)
- Pendulum: Pendant; Ratchet: Spur gear (9 teeth) (owner to confirm ratchet guess)
- Small gray parts: Hour Wheel (gray)
- Fixed (not selectable, rendered as stainless steel: metalness 1 + a three.js RoomEnvironment reflection used only by these parts): M3/M4 screws, Shoulder Bolt (was "Part 2"), Pendulm Rod, 3mm dowels, 5mm tube
Known issue: two parts are both named "Hour Wheel" (white and gray). Rename the gray one in Onshape on next export; until then distinguish by material color.
Test the mapping without a browser: a Node script loading the GLB with three's GLTFLoader + MeshoptDecoder and running `zoneForPart` on every mesh (Node 25 imports .ts directly).

## 3D viewer and configurator
- `components/ClockViewer.tsx` (client component): loads the GLB with drei `useGLTF`, tags each mesh with its zone, repaints from the shared color store, outlines edges with `EdgesGeometry` (EDGE_ANGLE = 30°, ~151k segments, ~0.3 s; outlines have raycast disabled so clicks hit parts).
- Orientation: Onshape exports Z-up; the model is rotated -90° about X, then 180° about Y so the face points at the camera.
- Controls mirror Onshape: scroll zooms toward the cursor; left/right-drag rotate; middle-drag or Shift+drag pan; "Reset view" re-fits. Framing is custom (`FitCamera` in ClockViewer, FIT_MARGIN): drei `Bounds` was dropped because it fits the largest dimension as if the clock were square, which wasted space in a tall cell. Zoom limits 0.05–2.5 m.
- Mouse: "click to explore": wheel zoom is off until the visitor clicks the clock (so the wheel scrolls the page); ends on pointer leave.
- Touch (no modes, so nobody gets stuck): one finger up/down always scrolls the page, sideways turns the clock (OrbitControls ONE: ROTATE), tap picks a part. Two fingers are custom (`TwoFingerGestures` in ClockViewer; OrbitControls TWO set to an invalid value to disable its own): pinch zooms toward the fingers, sideways moves the clock, up/down scrolls the page. `.touch * { touch-action: pan-y !important }`: r3f's wrapper div also sets `touch-action: none`, and the browser obeys the strictest ancestor, so styling only the canvas isn't enough.
- Test touch with Playwright + CDP `Input.dispatchTouchEvent` (real multi-touch; Playwright's own API only taps).
- Configurator = click a part: hover glows the whole zone, click (not drag; `e.delta > 4` = drag) opens `components/PartPicker.tsx` with filament swatches. On narrow screens (<560px) the picker is a full-width sheet `position: fixed` to the bottom of the screen (the viewer is taller than the screen, so its own bottom may be off-screen), with a slide-up animation. On desktop it scrolls itself into view if it opens partly off-screen.
- Shared color store: `components/ClockColors.tsx` (React context). Updating colors also rewrites the site accent CSS variables (`--red/--blue/--yellow` and `--red-text` for readable button text) and the browser theme-color meta tag.
- Filaments: `data/filaments.json` (id, name, hex) — the 30 solid Bambu Lab PLA Basic colors, hex codes from Bambu Studio's `resources/profiles/BBL/filament/filaments_color_codes.json` (gradients left out). Zone defaults in `data/zones.ts` (= the "Mondrian" preset) are the owner's Onshape colors snapped to the nearest filament in CIELAB: white→Jade White, red→Red, yellow→Sunflower Yellow, sky blue→Cyan, black and dark gray→Black (owner wants one black), light gray→Light Gray. Accents moved off the (now white) face: `--yellow` follows the escape wheel, `--blue` the motion works wheel.
- Presets: `data/presets.ts`, in button order: Mondrian (= the default clock), Ravens, Maryland, Orioles, Pink (Maryland, Ravens, Orioles, Pink are owner-picked). Each names a filament per zone by its exact name, plus a `strip` of filament names for the button's color squares (no duplicates); a misspelling fails the build. Buttons in `components/Presets.tsx`, in a hero sidebar cell under the specs (above the clock on phones). Owner will fine-tune the schemes.
- Design mode (`npm run dev` only, via `DESIGN_MODE` in `lib/colors.ts`): free color picker in each popup and a "Copy colors" button. Hidden in production.
- Unmapped parts render magenta (`#ff00ff`) and log a console warning.
- Exploded view (2026-11-18): an "Assembled ↔ Exploded" slider, built from the GLB alone (no Onshape exploded view). Plan computed once in `planExplode` (ClockViewer), owner's rules, like a sandwich: the back frame (a deep tray) never moves; every other printed part gets its own layer in the owner's assembly order (`STACK_ORDER` in `data/explode.ts`: barrel, ratchet, 3rd, 4th, [escape wheel + drive wheel], 2nd, [pallet + pendulum]; owner gave all but the ratchet's spot; an entry can be a list = one shared layer; unlisted parts go after by depth). The going-train layers are spaced by each part's main plane (`planeOf`: depth averaged over surfaces weighted by how much they face front/back, so a gear's disk outweighs its hub and pinion), GEAR_SPACING (55 mm) apart; face-to-face gaps looked uneven because hubs and pinions stick out. Later sections (time train, dial, hands) still use face-to-face EXPLODE_GAP. stacked with an equal EXPLODE_GAP (15 mm) between each part's back face and the previous part's front face, starting in front of the back frame (accounts for thickness, so gaps look even); then the time train (`TIME_TRAIN`: motion works wheel, both hour wheels, minute arbor; each its own layer, BEHIND the dial); then the dial as one layer (front frame + numerals printed on it); then the two hands in front, each its own layer; the M4 frame bolts (`isFrameBolt` in zones.ts) are the only parts that slide out the back. Pins/tube/small screws are locked to their host: the printed part centered on them (within 10 mm across, overlapping in depth), else the smallest part they sit inside; the pendulum rod follows the pendulum. The pendulum and rod are the only parts that also move down (owner): rod ROD_DROP (6 cm) below the pallet, pendulum a further PENDULUM_DROP (6 cm) below the rod; "down" = from the clock's middle toward the pendulum along the tallest axis. The fit-to-box shrink checks width and height. `ExplodeAnimator` eases toward the slider value, turns the clock EXPLODE_TURN (40°), measures its width each frame and shrinks it to the assembled width × EXPLODE_FIT (0.75, perspective allowance), anchored just below the top, re-centered left-to-right. `<Center>` sits inside the turning group. The slider sticks to the bottom of the screen (`position: sticky` in a full-height track; needs `.viewer { overflow: clip }`, not hidden).

## Design
- Warm Bauhaus: tokens in `app/globals.css` (paper #f2ede3, ink #141414, red/blue/yellow accents that follow the clock colors). Fonts Jost + IBM Plex Mono via `next/font`.
- Grid rules: containers are ink-colored with a 3px gap; cells are paper-colored, so gaps read as black lines.
- Hero (`components/Hero.tsx`): ~38% sidebar (intro, specs list, empty window cell, red/blue blocks at the bottom) and ~62% clock cell. Goal (owner): the clock's head (everything but the pendulum) fits on one screen; scrolling reveals the pendulum. Cell `height: min(--fit-width, --fit-screen)`: width-based uses the clock's shape 0.46 via `cqw` (hero is a size container); screen-based is `(100svh - 4rem) * 1.72` (head = 56% of clock height, with FIT_MARGIN). Don't use aspect-ratio + max-height: that shrinks the cell's width too. Retune 1.72 if FIT_MARGIN or the model's proportions change. FIT_MARGIN 1.12 (owner found 1.04 slightly too large on desktop). Columns `2fr 1fr 3fr 10fr`.
- Owner preferences: color should be dwarfed by paper/ink; amount of color red > blue > yellow; avoid busy UI.
